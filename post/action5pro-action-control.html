给Action 5 Pro做了一个管理后台

发表于 2026-09-27 评论数： 本文字数： 2.7k 阅读时长 ≈ 10 分钟

　　上篇给 Action 5 Pro 解锁 BL 并开启 adbd之后，相机已经有了开机自启的 root ADB。既然里面是一套能跑自己程序的 Linux，总不能拿到 root 之后就只用来敲两行命令吧。
　　于是，我给它做了一个网页管理后台，叫 Action Control。目前已经实现了浏览文件、整理相册、拍照录像、系统状态显示等功能。

项目地址：AlliotTech/action-control，原创代码采用 MIT 协议开源。

本项目面向 DJI Osmo Action 5 Pro（AC204），需要相机已经解锁并启用 root ADB。还没开 ADB 的朋友，先看上一篇 给 Action 5 Pro 解锁 BL 并开启 adbd。

简介

　　这是一个 Go + React 实现的 web 项目，编译成了一个二进制包，通过 adb 安装到相机并通过 systemd 来保持后台运行。
同时为了方便预览，配合 Astra 大人逆向了相机的固件， 以插件的形式注入到了相机的原生菜单。
打开相机设置滑到最底下可以看到一个 Action Control 的菜单，点击进去能够点击切换相机的热点模式，并提供了2个二维码，手机扫描第一个二维码能够连接上相机的热点，第二个二维码则可以打开 Action Control 的管理后台，你可以不用下载任何APP就能实现在线预览、相册管理、下载等功能，这个在外面和朋友玩耍时，可以很方便的将素材给朋友下载，而避免需要下载 DJI Mimo 这个超大APP的尴尬。

效果展示

目前能做什么

文件管理和相册

　　这部分比较直接，SD 卡和内置存储都可以浏览，上传、下载、重命名、删除。

　　相册则是另一种看文件的方式，可以搜索、按照片或视频筛选、排序、按日期分组，也可以放大图片、跳转到文件所在的位置。

　　顺带做了一件相机上比较有意思的事：读取它自己的媒体索引 AC004.db。除了文件本身的信息，还能看到相机记录的星标、精彩标记，以及部分拍摄参数。不过有些字段目前还只是原始值。 由于这个 db 文件存了素材的元数据，在直接删除素材文件的时候可能会留下孤儿数据，所以我也加了一个清理索引的功能在设置页面。

原生拍照和录像

　　参考了一些开源的逆向APP，扒了一下它们的协议，现在可以直接从网页开始、停止原生录像，也可以在相机空闲时切换拍照 / 视频模式，再调用原生拍照。拍摄和文件保存仍然交给相机自己的服务处理，沿用相机当前的拍摄设置，这些控制本身不需要 Mimo。
　　分辨率、帧率、编码、防抖等视频设置目前可以读取，但还不能在网页里随意修改；模式切换也只开放了已经验证的拍照和视频档位。

　　实现上，是读取相机已经发出的那份视频报文，校验、重组，再封装成 MPEG-TS 给网页播放器。没有重新编码，也没有另起一个原生预览订阅。多个网页会共用转发，最后一个连接关闭后释放对应资源。

　　所以，Mimo 退出预览、切到相册，或者进入后台后停了视频，网页这边也就没得看了。同一部手机在 Mimo 和浏览器之间来回切，反而容易把预览切断，建议拿另一台设备看。现在还不能把它当成一个开机就有画面的网络摄像头，更没有一个可以随便填进播放器的 RTSP 地址。

网络和相机后屏入口

　　默认情况下，Action Control 不接管相机的无线网络，而是复用原生连接。相机开了原生热点以后，手机或电脑连上去，就可以通过 http://192.168.2.1:8080 访问后台；已经有局域网连接的话，也可以用相机对应的 IP。

　　网页里的“原生热点”按钮，调用的是已校验固件中 dji_network 自己的热点入口，不是再拉一套 hostapd / dnsmasq 跟原生服务抢网卡。不过热点开关本身会切换无线状态，当前网页可能断线，这个别误以为是后台挂了。

　　除了网页，还给相机后屏加了一个入口：原生“系统设置”列表末尾的 Action Control 面板。里面有热点开关，以及加入 Wi-Fi、打开控制台地址的两个二维码，省得每次手输地址。

　　这个后屏扩展随安装、更新一起部署，但它依赖特定固件的界面结构，会先核对程序指纹，不匹配就保留原生插件行为。不是随便一台大疆相机都能装，更不能因为名字里都带 Action，就直接往其他型号上试。

　　后台也保留了独立网络管理模式，可以扫描、连接 Wi-Fi、管理已保存网络和热点，不过这与默认的原生模式是两回事。默认原生模式不提供独立扫描、连接和自动接管，也不保证相机熄屏后还能一直联网。

为什么不直接把原生服务停掉

　　拿到 root 以后，停止原生服务，再自己接管采集，当然也是一条路。项目里就保留了这样的“高级：独立采集”入口，可以输出 H.264 / MPEG-TS 画面、保存快照。

　　但问题在于，相机不是只跑着一个摄像头进程。独立采集会停止原生相机、屏幕和 Mimo 通信服务，停掉独立采集以后，想恢复原生功能仍可能需要重启。只是想远程按一下快门，结果把相机自己的功能都停了，这就有点本末倒置了。

　　所以目前默认走的是复用原生服务。相机控制通过它现有的客户端库和本地 Binder 服务完成，Go 后端再通过设备自带的 Python 3 / ctypes 去调用。原生库放在单独的子进程里执行，调用前校验型号、架构和库文件的 SHA-256，不匹配就不调用，而不是换个固件还照着原地址往里冲。

　　这也决定了它现在的边界：已经核对清楚的功能才开放，不确定的状态就显示不确定。相机实体按键、Mimo 和网页同时操作的各种组合，还不能说都验证过了。日常使用建议先保持默认模式，高级独立采集留给清楚它会停掉哪些服务的人。

构建安装包

　　先提醒一句：目前 Releases 里的 action5pro-unlock-files.zip 是上一篇用的解锁文件，不是 Action Control 安装包。控制台目前可以从源码构建。

　　构建在 macOS 或 Linux 上进行，需要仓库固定版本的 Node.js、Go，以及 curl、tar、make。当前要求 Node.js 24.20.0、Go 1.27.1，后续以仓库的 README 和 .tool-versions 为准。

　　脚本会构建媒体工具、前后端和安装包，结果在 release/ 下。进入生成的版本目录，或者完整解压对应的 .tar.gz，确认里面有 payload/、SHA256SUMS 和安装脚本。

结语

　　对我来说，拿到 root 之后能真正给设备加点自己想要的功能，才是折腾比较有意思的地方。一台运动相机当然还是先把拍摄做好，不过在不接管原生采集的情况下，多一个浏览器入口来管文件、看状态、控制拍摄，也挺实用。
　　代码和原生接口、预览协议的研究记录都放在仓库里了，有兴趣的朋友可以看看。还是那句话，搞机有风险，折腾需谨慎。
